## Security changes

- Lovable confirmed leaked-password/HIBP protection enabled through the existing auth setting. Existing sessions and other auth settings were preserved. This does not retroactively check existing passwords.
- Analytics clients send to `ingest-telemetry`. Direct anon/authenticated table privileges and permissive insert policies are removed from app_events, app_errors and page_views. The endpoint validates optional JWTs, derives user identity, accepts at most 8 KiB, strips arbitrary properties/private error text, and permits explicit deployed/preview/local origins. CORS is a browser control, not authentication.
- An atomic service-only SQL function limits accepted telemetry to 120 events per actor per minute and 1,000 project-wide per minute. Actor identifiers are daily HMAC hashes; no raw IP is stored. The global cap remains effective when network headers are spoofed. These limits bound accepted database writes; they do not eliminate invocation-level denial of service. Analytics remains best effort and is never authorization or payment evidence.
- Legacy daily_readings and daily_scriptures become server-only. No browser database consumer was found; the reminder worker uses service role. The separately reviewed formation-content gates are unchanged.
- Certificates become private. Owner-folder RLS permits only the owner to sign a five-minute download URL; the shared blank-template exception was removed in the ownership follow-up. New records store stable paths; old public URL records normalize to the same paths. Opening/downloading renews access. Old public certificate links stop working by design because certificates can contain names and private reflections. Public share text remains separate.
- Updates resolve patched dependency advisories, including React Router 7.18.4, selector parser 7.1.7 and vulnerable esbuild versions. Lovable tagging remains installed; Drizzle source/migrations are untouched.

## OAuth follow-up

Wearable and integration OAuth now issue opaque 256-bit, ten-minute requests stored as hashes in a service-only table, with one pending request per account/provider. User UUID, provider and return origin are written by the authenticated start handler. Caller-provided redirect destinations and old unsigned base64 states are ignored/rejected. Return origins are limited to the owned deployed/preview apps and loopback development.

The provider's unauthenticated GET callback exchanges no token and writes no connection: it redirects only to the trusted app, carrying the temporary authorization code in a fragment. The app removes that fragment before telemetry starts, then finalizes through an authenticated POST. The server requires the initiating UUID and atomically consumes the nonce before token exchange. This extra authenticated step prevents a copied state from attaching one account's provider to another account. Replays, expiry, tampering and wrong-family requests fail closed. Provider cancellation returns a fixed reconnect message, without interpreting provider-supplied HTML or redirect URLs.

Popup messages must match both the exact popup and the app origin, and UI success is confirmed against the saved owner-scoped connection. Existing provider scopes, callback URLs, credentials and stored connections are preserved. Tests mock all third-party exchanges; no new provider permission or real health data was used. The callback gateway permits GET returns; POST exchange performs explicit `auth.getUser` validation, while the wearable start keeps JWT verification enabled. Previously protected reminder/insight JWT settings stay true.
